# Stroll Privacy Policy

## 1. Introduction

This Privacy Policy explains how the Stroll mobile application collects, uses, stores, and protects information associated with its users.

Stroll is an Android application designed to encourage physical activity through step tracking, walking quests, maps, statistics, achievements, and virtual rewards.

This document describes the intended data-processing practices of the project. It must be reviewed and updated to reflect the actual implementation before the application is publicly released.

## 2. Scope

This policy applies to information processed by the Stroll Android application and its integrated services, including Google Account authentication, Google Fit, Google Maps, Firebase, and Firebase Cloud Messaging.

The policy covers user profiles, authentication-related information, activity records, quest progress, achievements, settings, and location-related information where the relevant functionality requires it.

## 3. Information We May Collect

### 3.1 Account Information

The application may process a user identifier and basic account information made available through the selected Google authentication configuration, such as a name or email address, if the corresponding permissions and implementation require them.

Stroll does not need to collect or store the user's Google account password.

### 3.2 Physical Activity Information

The application may process step counts, activity timestamps, calculated distances, and other supported physical activity information obtained from Google Fit or compatible device sensors.

This information is used to calculate progress, complete quests, generate statistics, and award achievements.

### 3.3 Quest and Achievement Information

The application may store selected quests, quest progress, completed objectives, experience points, unlocked achievements, and virtual rewards.

### 3.4 Location and Map Information

If a feature requires location access, the application may process location information to display or support walking routes.

Location permissions should be requested only when necessary for the selected functionality. The application should not collect continuous location information unless the implemented feature requires it and the user has been appropriately informed.

Map requests may also be processed by Google Maps services under Google's applicable terms and privacy documentation.

### 3.5 Application and Technical Information

The application may process settings, synchronization status, diagnostic information, and technical error information required to maintain its functionality.

Diagnostic logs should not contain passwords, authentication tokens, or unnecessary sensitive information.

## 4. Purposes of Data Processing

Information is processed for the following purposes:

- Creating and maintaining user accounts.
- Retrieving and recording physical activity information.
- Calculating step totals and walking distances.
- Tracking quest progress and awarding achievements.
- Displaying daily, weekly, and monthly statistics.
- Sending activity reminders and achievement notifications.
- Synchronizing data between local storage and Firebase.
- Troubleshooting errors and improving application reliability.
- Protecting accounts and preventing unauthorized access.

The application should not use personal information for unrelated purposes without an appropriate legal basis and, where required, the user's consent.

## 5. Data Storage

Stroll may store activity records and other application information locally on the Android device to support offline operation.

Firebase may be used to store and synchronize user profiles, activity records, quest progress, achievements, statistics, and settings.

The exact information stored locally or in the cloud depends on the final implementation.

The application should use appropriate access controls and secure communication. Cloud access must be restricted so that users cannot access another user's private records without authorization.

## 6. Third-Party Services

Stroll may rely on the following services:

- Google Account authentication for account access.
- Google Fit or supported Google activity services for physical activity information.
- Google Maps for map and route-related functionality.
- Firebase for cloud storage and synchronization.
- Firebase Cloud Messaging for push notifications.

These providers may process information according to their own terms, privacy policies, and technical configurations. Users should consult the relevant provider documentation for details about the provider's processing practices.

The application should disclose the services it actually uses and the data shared with each service.

## 7. Data Sharing

Stroll does not intend to sell users' personal information.

Information may be transmitted to the integrated services when necessary to provide authentication, activity tracking, mapping, cloud synchronization, or notifications.

Access may also be provided when required by applicable law or necessary to address security incidents, subject to relevant legal requirements.

The application should not share personal information with unrelated third parties for advertising or other purposes unless such processing is separately disclosed and legally justified.

## 8. Data Retention

Personal information should be retained only for as long as necessary to provide the application's functionality, comply with applicable obligations, resolve disputes, and protect the system.

The final implementation should define retention periods for account records, activity history, diagnostic logs, and backups.

Where supported, users should be provided with a way to request deletion of their account and associated data. Deletion procedures should account for local records, cloud records, and applicable backup-retention limitations.

## 9. User Choices and Permissions

Users can manage relevant Android permissions through the device settings.

Users should be able to understand why physical activity, location, notification, or account permissions are requested.

Where supported by the implemented functionality, users should be able to review their activity history, manage notifications, sign out, and request deletion of their account and associated information.

Revoking a permission may limit the corresponding feature.

## 10. Data Security

Stroll applies appropriate technical and organizational measures to protect information against unauthorized access, loss, disclosure, and modification.

These measures include authentication, access restrictions, secure network communication, local data protection, input validation, and controlled access to project infrastructure.

No software system can guarantee absolute security. Suspected incidents involving personal information should be assessed and handled in accordance with applicable requirements.

## 11. Children's Privacy

Stroll is intended for a broad audience, but the final release must determine whether additional requirements apply when children use the application.

If the application is made available to children, the project team must assess applicable age-related privacy requirements, consent rules, data collection restrictions, and platform policies before release.

The application should not collect unnecessary personal information from children.

## 12. Changes to This Policy

This policy may be updated when the application's functionality, data processing, or legal requirements change.

Significant changes should be communicated through an appropriate application interface or another suitable communication channel.

## 13. Contact Information

For privacy-related questions or requests, users should contact the project team through the contact details published with the application.

The final public version must include a valid contact address or other appropriate contact method before release.
